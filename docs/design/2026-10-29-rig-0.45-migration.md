# Rig 0.37 → 0.46 迁移记录

> 日期：2026-10-29
> 范围：`src-tauri` 中所有使用 `rig` 的代码（provider 适配层、工具系统、记忆 embedding、消息构造）

## 背景

`src-tauri/Cargo.toml` 把 `rig` 从 `0.37` 升到 `0.45`（`Cargo.lock` 已解析到 `0.45.0`），但源码仍停留在 0.37 的 API 上，`cargo check` 报 26 个 E0432/E0433/E0425。Rig 0.45 对公共 API 做了一次整体重塑，因此这是一次结构性迁移，不是简单改签名。

## 0.45 的核心变化

| 主题 | 0.37 | 0.45 |
|------|------|------|
| 客户端 | `providers::openai::Client` | `providers::openai::OpenAI`（另有 `OpenAIConfig`），`deepseek`/`groq`/`moonshot` 提供 `new()` / `from_env()` |
| 构造 | `Client::new(key) -> Result` | `OpenAI::new(key)` 直接返回；仅 `from_env()` 返回 `Result` |
| 模型 | `client.agent(id)` 直接返回 agent | `client.chat(id)` / `completion(id)` / `embedding(id, ndims)` → `Model<Wire>` |
| 类型擦除 | 泛型 `CompletionClient` | `Model::erase()` / `From<Model<W,T>> for DynModel<W::Op>` |
| Agent | `AgentBuilder`（来自 client） | `rig::agent::AgentBuilder::new(model)`，`.preamble(..)`、`.dynamic_tools(..)`、`.build()` |
| 执行 | `agent.prompt/chat` 返回 `String` | `agent.prompt(..) -> AgentRunner`；`.await` → `PromptResponse::output()`，`.stream()` → `StreamingResult` |
| 流事件 | `StreamedAssistantContent::Text` | `MultiTurnStreamItem::StreamAssistantItem(Item::Event(StreamEvent::Text { .. }))`，终态 `FinalResponse` |
| 工具 trait | `rig::tool::ToolDyn`（object-safe） | 无 object-safe trait；`rig::tool::Tool`（`Sized`）+ 运行时 `DynamicTool` |
| 工具集 | `ToolSet::builder().static_tool(..)` | `ToolSet::from_tools()` / `add_dynamic_tool()`；agent 侧 `dynamic_tools(Vec<DynamicTool>)` |
| 工具错误 | `ToolError::{JsonError, ToolCallError}` | `ToolExecutionError`（按 `ToolErrorKind` 分类）、`ToolOutput` |
| 消息 | `Message::{System, User{OneOrMany}, Assistant{content,..}}` | `Message::Assistant(AssistantMessage { content, origin, stop })`；user content 为 `Vec<UserContent>` |
| 工具结果消息 | `Message::tool_result_with_call_id(id, call_id, content)` | `Message::tool_result(CallId, ToolName, content)` |
| 提取 | `client.extractor::<T>(id)` | `rig::extractor::ExtractorBuilder::<T>::new(model).build()` |
| Embedding | `client.embedding_model(id)` + `EmbeddingModel` trait | `client.embedding(id, None) -> Model<Embeddings>`；`embed_text()` 是固有方法（或 `DynModel<Embedding>`） |

## 实现方案（本项目）

### 1. Provider 适配层（`api/rig.rs`、`api/provider.rs`）

- `RigProvider<C: CompletionClient>` → `RigProvider { model: DynModel<Completion>, model_id: String }`
  - 泛型参数消失后，`ProviderRegistry` 里只剩一种类型，`Arc<dyn ProviderBox>` 的桥接不再需要为每个后端单态化一次。
- `create_rig_provider()` 逐个 provider 构造 model 后即擦除：
  - OpenAI / Groq / DeepSeek / Moonshot / OpenAI 兼容 → `.chat(id)`（沿用 Chat Completions 语义，避免 0.45 默认的 Responses 路由）
  - Anthropic / Gemini → `.completion(id)`
  - Ollama → `.completion(id)`，`OllamaConfig` 把 URL 收敛到 daemon 根路径
- 每次调用用 `AgentBuilder::new(model.clone()).preamble(..).build()`；不再复用 agent 实例。
- `prompt_with_tools` / `stream_with_tools` 的形参由 `ToolSet` 改为 `Vec<DynamicTool>`（agent 只接受 DynamicTool 列表）。
- 流式输出保持原有契约（纯文本增量）：只取 `StreamEvent::Text` 和 `FinalResponse`，其余 item 映射为空串。
- `extract_structured::<T>()` 改用 `ExtractorBuilder`，返回 `TypedPromptResponse::output`。

### 2. 工具系统（`tools/`、`mcp/`）

Rig 0.45 没有可存储的 object-safe 工具 trait，但项目需要「内建工具 + 动态 MCP 工具 + 脚本工具」的异构集合，因此在 `tools/trait.rs` 保留自有契约：

```rust
pub trait AgentTool: Send + Sync {
    fn name(&self) -> String;
    fn definition(&self) -> ToolSpec;                 // name / description / parameters
    fn call<'a>(&'a self, args: String)
        -> Pin<Box<dyn Future<Output = Result<String, ToolError>> + Send + 'a>>;
}
```

- `ToolError` 保留旧的 `JsonError` / `ToolCallError` 两分支，工具实现体几乎零改动；仅在边界 `impl From<ToolError> for ToolExecutionError` 一次性转换。
- `ToolRegistry::to_rig_tool_set()` → `to_rig_tools(&self, allowed) -> Vec<DynamicTool>`：把每个 `Arc<dyn AgentTool>` 包进 `DynamicTool::new(ToolName, description, parameters, closure)`，回调转发 `AgentTool::call` 并用 `ToolOutput::text` 包装结果。
- `mcp/bridge.rs`、`mcp/manager.rs` 的 `McpToolBridge` / `McpToolWrapper` 同样改为 `impl AgentTool`。

### 3. 记忆 embedding（`memory/mod.rs`）

- 字段由 `Option<rig::providers::openai::EmbeddingModel>` 改为 `Option<DynModel<Embedding>>`，构造为 `OpenAI::new(key).embedding(TEXT_EMBEDDING_3_SMALL, None).erase()`。
- `embed_text()` 调用点不变（返回的 `Embedding.vec` 仍是 `Vec<f64>`）。

### 4. 消息构造（`commands/session.rs`、`lifecycle/compactor.rs`、`agent/loop.rs`、`orchestrator/planner.rs`）

- `Message::Assistant { content, .. }` → `Message::Assistant(turn) => turn.content`。
- `content.first_ref()` → `content.first()`（`OneOrMany` 已变成 `Vec`）。
- 持久化的 tool 消息没有工具名：新增 `tool_result_message()`，用 `CallId::from_wire(tool_call_id)` + 占位名 `tool` 重建 `Message::tool_result`。
- `tool.definition(String::new()).await` → `tool.definition()`（同步方法）。

### 5. 测试

- `tests/tool_calculator.rs`：导入改为 `AgentTool`。
- `tests/llm_tests.rs`：原来是一段不能编译的临时草稿，改为三个真实用例——为 7 个原生后端各构造一次 provider、验证 OpenAI 兼容后端能吃掉带 `/chat/completions` 的完整 URL、验证默认 base URL 分支。全部离线执行，不发请求。

## 0.46 更新（2026-11-02）

- `src-tauri/Cargo.toml`：`rig = "0.45"` → `rig = "0.46"`，`Cargo.lock` 解析到 `0.46.0`（`rig-core` / `rig-agent` / `rig-memory` 等同步升级）。
- 0.46 的 breaking change 集中在上游 CLI/TUI、plugin/ECS、memory 与 provider 内部（如 `Native::reasoning_blob`、`Quirks`、Ollama 家族命名）；本项目只用到 `AgentBuilder`、`DynamicTool`、`Message`、`ExtractorBuilder` 和 embedding model，签名未变，**源码零改动**。
- 0.46 的「静默行为变化」（默认 system prompt、内置 shell/read 工具、工具输出编码等）不涉及本项目：preamble 由业务代码显式传入，工具全部是自实现的 `AgentTool`，不使用 Rig 内置工具与 CLI。
- 验证：`cargo check --all-targets` 通过（仅既有 `dead_code` 警告）。

## 遗留问题

1. **`api/util.rs` 的 `extract_json` 泛化围栏分支有缺陷**：输入以 ` ```json ` 开头时，先匹配 ` ```json ` 失败（空块）后，通用 ` ``` ` 分支会把 "json" 当成内容返回，导致 `test_empty_fence_skips_to_next_heuristic` 失败。修复方式：通用分支跳过已识别的 `json` 语言标记（或先剥离语言标识）。
2. **宿主机 App Control 策略**拦截 `~/.cargo/bin/*.exe` 与 `target/debug/deps/*.exe`；临时绕过方式是直接调用
   `%USERPROFILE%\.rustup\toolchains\stable-x86_64-pc-windows-msvc\bin\cargo.exe`（编译可行，但新生成的测试 exe 仍会被拦截）。
3. 构建期沙箱只授予工作区根目录写权限，`target/` 子目录被拒，`cargo` 需要以完全访问权限运行。
